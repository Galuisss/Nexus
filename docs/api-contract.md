# API and protocol contract

UI behavior is specified in [UI specification](ui-spec.md); setup and usage are covered in the [guide](guide.md).

Nexus exposes an HTTP JSON API, SSE, and MCP over Streamable HTTP or stdio. Codex owns in-session execution and history; Nexus also executes machine-level commands and transfers files independently. Runtime connections reuse the shared daemon through `codex app-server proxy`; local spawn mode is available for isolated runtimes. SSH uses argv, never a shell-built local command. Explicit demo mode supplies interactive example data.

`GET /features` returns `{toolCallId:boolean}`; `PATCH /features` updates that default and publishes `nexus/features/updated`. It defaults to false and applies to newly created root conversations. Existing conversations retain their creation-time choice; derived conversations inherit their source's ID capability. Thread settings include `toolCallId` and `toolCallCompact`. Only `toolCallCompact` is mutable through `PATCH /machines/{m}/threads/{t}/settings`; it requires an ID-enabled conversation and remembers the last value as the default for new enabled conversations.

ID-enabled conversations route native Responses requests through `/tool-context/{token}/...`, retaining their provider credentials in transit and their native call associations. Omitted provider base URLs use the account's native ChatGPT or OpenAI API default. IDs follow top-level function/custom-call emission order, appear on returns, and key archived originals. Projection keeps earlier compacted returns stable across subsequent requests. Fork numbering is reconstructed from its actual inherited context. Native context compaction retains a numbering checkpoint. SSH uses the existing reverse tunnel.

Tool-call compaction selects unmarked original text of at least 2,048 `o200k_base` tokens. It appends the retention policy followed by a developer message containing only the eligible-ID JSON array, discards that exchange, then resumes normal serving with projected returns. Summaries retain only facts from their own return that are useful for subsequent work; unnecessary original information may be omitted. Short, media and original-read returns require no compression decision. Failed decisions and projections that increase tokens, including labels, retain the marked original. `toolCallCompaction` status items use ordinary `item/started` and `item/completed` events, with `startedAtMs`, `completedAtMs`, status and serving usage. Each item's `results` contains `sourceId`, the native `call` and `original` return. Finished results add `outcome`: `compacted`, `keep`, `fallback_failed` or `fallback_growth`; only `compacted` includes `projected`. Nexus persists per-source outcomes and overlays the stored projections on snapshots/history for reconnects. Original bodies, decisions and compacting state live in the Nexus database.

Execution machines must be trusted devices privately controlled by the owner; their connection to the control machine can use any reachable network. Nexus's service endpoints for browser, CLI, and MCP clients should be exposed on a trusted LAN or Tailscale. Access to these endpoints is controlled by the network, and clients share the owner's machine and session permissions.

HTTP, WebSocket, and MCP share an explicit Host/Origin policy. Startup registers local interface addresses, the hostname, Tailscale names and Serve endpoints, plus loopback entries on the service port and SSH reverse port 18765. Repeatable `--allow-url` arguments add custom origins and their Hosts; `service install` persists them. Unknown Hosts receive HTTP 421; present, unlisted Origins receive 403; rejected WebSocket handshakes close with code 1008. Clients may omit Origin. Proxy Host rewrites must use a registered entry; forwarded headers do not expand the allowlist. Restart after interface changes to refresh discovered addresses.

Session management requires Codex CLI 0.169.0 or newer and configured model access on execution machines; independent remote commands require SSH and Bash. The control machine connects to Codex through local processes or standard non-interactive SSH over any network it can reach. SSH uses the control machine's system configuration and `StrictHostKeyChecking=accept-new` to record first-use host keys while rejecting changed keys; `host` accepts an IP address, hostname, or SSH config alias. Machine connections are independent of the network mode used to access Nexus.

Daemon connections use a control-side WebSocket/JSONL bridge between `app-server proxy` and the Python SDK. SSH carries the same native WebSocket stream; remote machines only run Codex.

Each SSH runtime connection also forwards remote `127.0.0.1:18765` to Nexus using `ssh -R` with `ExitOnForwardFailure=yes`. The remote SSH server must permit remote TCP forwarding and have that port available. The tunnel closes with the runtime connection and is recreated on reconnect, in both daemon and spawn modes.

On startup, the service connects all registered machines concurrently in the background. Individual failures appear in machine status and logs; the HTTP service remains available. Shutdown cancels pending startup connections and closes their transports. Demo mode uses its own simulated machines.

Failed and unexpectedly closed connections retry after 1, 2, 4, 8, 16, then 30 seconds. Manual disconnect cancels retries. Reconnection restores observed sessions and refreshes their active turn; a turn completed during the outage emits its completion after recovery. Machine status uses `connecting`, `connected`, `reconnecting`, and `disconnected`; reconnecting retains the last connection error. Each queued runtime event carries its source connection; events from closed or replaced connections are discarded. A failed event is logged and emits `nexus/resync` while dispatch continues.

Nexus serves stateless Streamable HTTP MCP at `/mcp`. After initialization, each SSH runtime connection replaces the remote user's global `mcp_servers.nexus` entry through `config/batchWrite` with `reloadUserConfig:true`, then calls `config/mcpServer/reload`. The endpoint is `http://127.0.0.1:18765/mcp`. Other MCP entries are preserved. Remote agents can manage all registered machines through this endpoint.

MCP `execute_command(machine_id,command:string[],cwd,timeout_seconds=60)` calls `POST /machines/{m}/commands` and returns its result directly. Execution uses a local subprocess or the registered SSH settings, independently of the machine's Codex connection. Remote execution uses Bash's login environment. Commands use argv; shell syntax requires an explicit shell invocation. The execution identity is the Nexus process user locally or the SSH login user remotely. Demo machines reject execution.

MCP `capture_screenshot(machine_id,include_path=true,serial?,timeout_seconds=15)` calls `POST /machines/{m}/screenshot` and returns native MCP image content with MIME type `image/png`. By default, also saves the PNG in `${XDG_CACHE_HOME:-$HOME/.cache}/nexus/screenshots/` on that machine and returns the absolute path as a text block. Set `include_path=false` for an image-only response held in memory. Runs `adb [-s serial] exec-out screencap -p` on the registered machine. A phone executing through Termux needs its local ADB connected to itself. Omit `serial` for a single ADB device. Binary output has a separate 16 MiB limit.

MCP `get_phone_numbers(machine_id,serial?,timeout_seconds=15)` calls `GET /machines/{m}/phone-numbers?serial=&timeoutSeconds=15`, returning `{subscriptions:[{subscriptionId,slotIndex,carrierName,number}]}` for active SIMs. Slot indices are zero-based; numbers retain Android's format, with `null` for unavailable numbers and an empty list for no active SIMs. Requires Android 13+ and a connected ADB device on the execution machine. The bundled DEX helper calls the named subscription service methods through `app_process` in a temporary directory, removed on completion. The HTTP response uses `Cache-Control:no-store`; timeout and cancellation follow machine command execution.

MCP `add_project(machine_id,cwd,create_directory=false)` and `remove_project(machine_id,cwd)` call the corresponding HTTP project endpoints and return the updated Machine. Both preserve other projects and the runtime connection, support offline machines, and are idempotent. Set `create_directory=true` to create a missing directory and its parents. `update_machine` retains full `projects` replacement support.

MCP `list_threads` accepts `scope=history|loaded` (default `history`) within tracked projects. History includes saved, unloaded conversations, sorted by recent activity; loaded returns all matching current runtime sessions without pagination. `archive_status=all|unarchived|archived` (default `all`) filters either scope; `search_threads` uses the same archive parameter for indexed history. Other list parameters are `machine_id?`, `search_term?`, `limit=50` per machine, and `cursor?`. For history, the first page returns `nextCursors` keyed by machine ID; continue with that `machine_id`, its cursor, and the same filters, then follow `nextCursor`. Returned threads retain `archived`.

The default server listens on `0.0.0.0` at the selected port, accepting Web UI, API, and MCP connections through any reachable IPv4 interface without Tailscale. `--tailscale-only` requires a connected Tailscale installation and listens on both its IPv4 and loopback, restricting remote access to the tailnet. An explicit `--host` selects a single address and is mutually exclusive with `--tailscale-only`. CLI clients default to `http://127.0.0.1:8765` in both modes; `--url` or `NEXUS_URL` selects another endpoint.

External reverse proxies can provide HTTPS for mobile PWA installation and notifications. In `--tailscale-only` mode, when a root HTTPS Tailscale Serve proxy targets the server's port, HTTP requests to `/` redirect to that HTTPS origin. API routes retain their HTTP behavior. Default mode serves `/` directly without probing Tailscale; HTTPS redirects are configured at the proxy.

Thread lists, search results and project activity use native `recencyAt`, falling back to `updatedAt` and `createdAt`. Search inventory scans and indexed content versions follow the same activity time. Content events and active turns also trigger history synchronization; title and archive changes update index metadata.

## HTTP

### Account limits

`GET /api/accounts/usage?refresh=false` → `{accounts,otherMachines}`. OAuth accounts group by `userId` and `accountId`; each includes `email,planType,workspaceName,machines,usage,updatedAt,error`. Machine members contain `id,name,status,error`. `usage` preserves the native `account/rateLimits/read` response, including `rateLimitsByLimitId` and `rateLimitResetCredits`. Window durations are minutes; reset and credit-expiration timestamps are Unix seconds. Reset-credit totals use `availableCount`; detail rows may cover fewer credits.

Identities come from `account/read` with `refreshToken:false`. Each account uses one connected machine for usage reads, trying another member on failure. Snapshots share a 30-second cache; `refresh=true` bypasses it. Account and connection events invalidate the cache. Failed reads retain the last usage and its timestamp. Non-OAuth and signed-out machines appear individually in `otherMachines` with `authType` and optional `providerName`. Responses use `Cache-Control:no-store`.

### Interactive terminals

Terminals belong to machines and run independently of Codex, using a local PTY or SSH PTY. Their processes and a bounded 2 MiB output history live in the Nexus service. Client disconnection leaves shells running. Service shutdown closes terminals; a lost SSH transport ends its shell connection.

- `GET /api/terminals` → `{data:Terminal[]}` across all machines, in creation order. Terminal fields: `id,machineId,cwd,threadId,name,createdAt,status:running|exited,exitCode,cols,rows`.
- `POST /api/machines/{m}/terminals` `{cwd?:"~",threadId?,cols?:80,rows?:24}` → Terminal (201). Home paths expand on the execution machine. A `threadId` reuses the existing binding for that machine, including an exited terminal until it is deleted. Other opens create a new terminal. Demo machines reject creation.
- `DELETE /api/terminals/{id}` (204) ends the process and removes its binding. Removing a machine closes its terminals.
- `WS /api/terminals/{id}/stream?after=0` attaches using a byte offset. The server sends `ready` `{reset,offset,end,cols,rows}`, followed by `output` `{offset,data}` with base64 bytes, and `exit` `{exitCode}`. `reset:true` resets the emulator when the requested offset is outside retained history. Clients send `input` `{data:string}` for UTF-8 text, `input-binary` `{data:string}` for base64 terminal bytes, `resize` `{cols,rows}`, and `ack` `{offset}` after rendering. Messages include their `type`. Output pauses PTY reading when an attached client falls 256 KiB behind. Detaching resumes background draining. Browser WebSockets must use the service's origin.

### Files

`POST /api/machines/{m}/files/create` `{directory,name,isDirectory}` → `{machineId,path}` (201). Creates an empty file or one directory in an existing absolute directory. `name` is a single filename. Existing names return HTTP 409.

`POST /api/machines/{m}/files/rename` `{path,name}` → `{machineId,path}` renames a file or directory within its parent. `path` is absolute; `name` is a single filename. Existing destinations return HTTP 409.

### Other endpoints

All paths below start with `/api`. Native Codex JSON fields retain camelCase.

- `GET /config` → `{app,version,demo}`
- `GET /health` → `{status,eventWorker}`. Returns HTTP 200 with `ok/running` while the event worker is running, HTTP 503 with `error/stopped` otherwise.
- `GET /push/key` → `{publicKey}`: persistent VAPID public key in base64url.
- `POST /push/subscriptions` accepts native `PushSubscription.toJSON()` and returns `{subscribed:true}`. Registers this device and observes loaded sessions for completion notifications.
- `DELETE /push/subscriptions` `{endpoint}` → `{subscribed:false}`.
- `POST /push/test` `{endpoint,testId?}` → `{sent:true}` after the push service accepts a test notification. With `testId`, the service worker reports `nexus/push-test` and that ID to open windows after calling the notification API; an `error` reports an API failure. A successful receipt confirms browser push reception and notification API completion.
- `GET /machines` → `{machines: Machine[]}`
- `POST /machines/{m}/commands` `{command:string[],cwd,timeoutSeconds?:60}` → `{exitCode,stdout,stderr,timedOut,stdoutTruncated,stderrTruncated}`. Runs a one-shot command on a registered machine; `cwd` is an absolute directory on that machine. `command` must be nonempty and `timeoutSeconds` positive. The timeout covers connection and execution; expiry stops the process group and returns captured output with `timedOut:true`. Cancellation also cleans up the process group. Each stream retains at most 1 MiB while draining excess output. SSH stdin closure stops the remote process group; a remote watchdog also bounds execution if the network disappears. Cleanup may take up to five additional seconds. Launch errors use the normal HTTP error response; nonzero exits and timeouts return the command result.
- `POST /machines/{m}/screenshot` `{includePath?:true,serial?,timeoutSeconds?:15}` → PNG bytes (`image/png`, `Cache-Control:no-store`). With `includePath:true`, also saves the image on the execution machine and returns its URL-encoded absolute path in `X-Nexus-Screenshot-Path`. Uses the command executor's local/SSH transport, timeout and cancellation cleanup, independently of Codex. ADB errors, invalid PNG output and images exceeding 16 MiB return HTTP 502; capture timeouts return HTTP 504.
- Machine fields `projects:string[]` and `projectActivity:{cwd:timestamp}` index registered directories and their latest session times. The first successful connection imports directories of loaded sessions with native status `active`, including input/approval waits, then persists `projectsInitialized:true`. Later connections and history reads update activity within registered projects. Manual project registration, session creation, and forks can add directories.
- `POST /machines/{m}/projects` `{cwd,createDirectory?:false}` → Machine. Checks the absolute project path on the target machine before persisting it. Missing directories return HTTP 404 with `error.code:directory_not_found`; an explicit `createDirectory:true` creates the directory and its parents, then registers the project. Existing files return HTTP 400 with `error.code:not_directory`. Local filesystem and SSH operations work independently of the Codex connection and preserve it.
- `DELETE /machines/{m}/projects` `{cwd}` → Machine. Removes a directory from tracked projects and activity metadata, persists the change, and publishes `nexus/machine/updated`. Available while the machine is offline. Sessions leave list, search, and completion notification scopes; files, native history, and running turns remain available on the execution machine. Repeated removal returns the current Machine; `POST` restores tracking.
- `GET /machines/{m}/directories?path=~` → `{path,parent,entries:[{name,path}]}`. Lists directories on that machine through native `fs/readDirectory`. The default is `~`; `~` and `~/` resolve against the machine user's home and responses contain absolute paths.
- `GET /machines/{m}/files?path=~&searchTerm=&mode=title|content|both` → `{machineId,path,parent,entries:[{name,path,isDirectory,size?,mimeType?}]}`. Local listings read the filesystem; SSH listings use native `fs/readDirectory`. The default path is `~`; home paths expand using the Nexus process user locally and the SSH login user remotely. Search matches literal text, ignoring case, within this directory's direct children. Title matches names; content matches readable text files; both combines them. An empty query lists all entries. Missing paths and paths that are no longer directories return HTTP 404 with `error.code:directory_not_found`; local permission errors return HTTP 403.
- `POST /machines/{m}/files` accepts multipart `directory`, repeated `files`, and optional `overwrite=false` → `{machineId,directory,files:[{name,path,isDirectory,size,mimeType}]}`. Saves original bytes, creates the target directory, and rejects existing names with HTTP 409 unless overwrite is enabled.
- `GET /machines/{m}/files/download?path=/absolute/file&preview=false` returns the file with its original name. Preview serves images inline. SSH downloads stage through the Nexus host and remove temporary files after the response.
- `PUT /machines/{m}/files/text` `{path,content,originalContent}` → `{machineId,path}`. Saves UTF-8 text to an existing absolute file path. The current bytes must match `originalContent` encoded as UTF-8; otherwise HTTP 409 with `error.code:file_changed` leaves the file unchanged. Local writes preserve permissions and follow symlinks; SSH reads and writes use native `fs/readFile` and `fs/writeFile`.
- `POST /files/transfer` `{sourceMachineId,sourcePaths:string[],targetMachineId,targetDirectory,recursive?:false,overwrite?:false}` → `{sourceMachineId,targetMachineId,directory,files}`. Both endpoints are registered machines and all paths are absolute. SSH legs use system `scp` with the registered SSH settings; remote-to-remote transfers stage through Nexus. Local copies use the filesystem. Target directories are created; directory copies require `recursive:true`. Overwrite merges directory contents. Transfer staging is removed on completion.
- `POST /machines` / `PATCH /machines/{machineId}` → Machine; fields include `name,transport:local|ssh,host,user,port,codexBin,connection:daemon|spawn,env,projects:string[]`. Machine registration does not take a working directory. New project paths must pass the same directory check as `POST /machines/{m}/projects` before saving or disconnecting. PATCH disconnects only when effective runtime settings change: transport, connection mode, executable, environment, or SSH host/user/port. Defaults are compared by their runtime values; local connections ignore SSH fields. Metadata and equivalent settings preserve the connection. Changed connection settings retain the explicit `connect` step. Replacing `projects` persists the list, prunes removed directories' activity, publishes `nexus/machine/updated`, and wakes search synchronization.
- `DELETE /machines/{machineId}`; `POST /machines/{machineId}/connect|disconnect`.
- `POST /machines/{machineId}/reconnect` → Machine. Cancels the current retry, rebuilds the connection immediately, and restores observed sessions and turn recovery. Failures resume automatic retries.
- `GET /search?searchTerm=&mode=title|content|both|id&view=recent|working|waiting&machineId=&cwd=&archived=&cursor=&limit=10` → `{data:Thread[],nextCursor,syncing,errors}`. Queries the persistent local index without runtime RPCs. Default mode is `title`. ID mode matches any case-insensitive thread ID suffix and ignores `cwd`, with multiple matches paginated normally. Scope is registered projects, optionally one machine/directory; Working and Waiting restrict session IDs before pagination. Recent includes archived history; omit `archived` to search both groups. Results sort by conversation activity with keyset pagination. Body matches add `searchMatch:{text}` containing a plain-text excerpt. Matching is a case-insensitive literal substring; SQLite FTS5 trigrams narrow queries of three or more characters, and shorter queries scan cached text.
- `POST /search/sync?machineId=` → `{syncing:boolean}`. Wakes background synchronization for one machine or all machines.
- `GET /threads?machineId=&scope=loaded|history&cwd=&archived=&searchTerm=&limit=50` → `{data:Thread[],errors:[],nextCursors:{machineId:cursor}}`. Lists top-level sessions within registered projects; subagents and side conversations are excluded. Threads add `machineId,machineName,archived`. `scope=history` includes both archive groups when `archived` is omitted; `true` selects archived history and `false` selects unarchived history. `limit` applies per machine.
- `GET /machines/{m}/threads?scope=loaded|history&cwd=&cursor=&limit=50&archived=` → `{data,nextCursor}` with machine metadata added to data. `scope=loaded` discovers loaded runtime sessions within registered projects; `scope=history&cwd=...` finds stored conversations in one registered directory. Native history queries pass the registered directories as the `cwd` filter before pagination. Combined history merges the two archive groups by conversation activity and returns an opaque cursor preserving both pagination positions.
- `GET /session-defaults` → `{model?,models:{[model]:{effort?,serviceTier?}}}`. Nexus shares these defaults across clients and execution machines.
- `POST /machines/{m}/threads` `{cwd,model?,effort?,serviceTier?,sandbox?,approvalPolicy?,name?,saveDefaults?}` → `{thread,machineId}`. Omitted model, effort and speed use compatible Nexus defaults, then the execution machine's configuration.
  Unnamed new threads generate and persist a short title after their first text message. Generation runs in a hidden ephemeral Codex thread; `thread/name/updated` delivers the result. Manual naming takes precedence.
- `GET /machines/{m}/threads/{t}` → `{thread}`. Runtime placeholders without readable dialogue return HTTP 404 with `code:empty_thread`.
- `GET /machines/{m}/threads/{t}/goal` → `{goal:ThreadGoal|null}` through native `thread/goal/get`. Disabled native goals add `supported:false`.
- `PUT /machines/{m}/threads/{t}/goal` `{objective?,status?,tokenBudget?,origin?:user|automatic}` → `{goal}` through `thread/goal/set`. Omitted fields retain their values; `tokenBudget:null` removes the budget. Activating the goal uses native automatic continuation. Archived threads are unarchived and attached before updating. UI mutations use `origin:user`; MCP mutations use `automatic`.
- `POST /machines/{m}/threads/{t}/goal/resume` `{origin?}` → `{goal}`. Sets native status `active` and retains the objective and accounting.
- `POST /machines/{m}/threads/{t}/goal/stop` `{origin?}` → `{goal}`. Sets native status `paused` before interrupting the current turn; retains objective, budget and accounting. Updating status to `paused` with PUT pauses continuation while the current turn finishes.
- `DELETE /machines/{m}/threads/{t}/goal` `{origin?}` → `{cleared}` through native `thread/goal/clear`; the current turn continues. MCP exposes `get_goal`, `set_goal`, `resume_goal`, `stop_goal`, and `clear_goal`.
  Native `ThreadGoal` includes `objective,status,tokenBudget,tokensUsed,timeUsedSeconds,createdAt,updatedAt,threadId`. Statuses are `active,paused,blocked,usageLimited,budgetLimited,complete`. State and snapshot responses include `goal` and `goalSupported`; `thread/goal/updated` and `thread/goal/cleared` events update the same cache.
- `GET /machines/{m}/threads/{t}/history?cursor=&limit=30` → `{thread,data:Turn[],nextCursor}`. Latest page first; turns contain full items. Measured assistant items add `nexusTps:{tokens,durationMs}`.
- `GET /machines/{m}/threads/{t}/state` → `{thread,settings,tokenUsage,compactionIds}`. `compactionIds` contains completed context compaction item IDs across the full thread history. Settings include native `model,reasoningEffort,serviceTier,collaborationMode,approvalPolicy,sandbox,summary`. Summary initializes from the working directory's effective `model_reasoning_summary` configuration and follows native settings updates. Usage retains native `last,total,modelContextWindow`; absent native usage is `null`.
- `GET /machines/{m}/threads/{t}/developer-inputs?preview=true` → `{baseInstructions:string,runtimeMessages:[{id,text}],customInstructions:string,source:saved|preview}`. Reads saved developer messages from the execution machine, following compressed rollouts and inherited byte boundaries. Compaction replacement history supplies the current context. Native content tags separate base instructions and custom developer instructions, including Nexus Tool call rules, from runtime messages; runtime messages retain their order and boundaries. ID-enabled threads supply their saved custom instructions before the first turn. With `preview=true`, threads without recorded developer inputs use the execution machine's native `codex debug prompt-input`, applying the working directory, model, effort, permissions and Nexus custom instructions. Preview creates an ephemeral debug context without sampling or sending a message to the thread. Omitting `preview` returns saved inputs only.
- `GET /machines/{m}/threads/{t}/context-usage` → `{source,attribution,model,tokenizer,modelContextWindow,usedTokens,nativeTotalTokens,categories,input,output,cache,samples}`. Replays inherited byte boundaries and compaction replacements. `attribution:native` uses persisted `rawResponse/completed.usageMetadata.metadata.attribution.items`, including per-content input, output and cache tokens; each ledger exposes native totals, classified totals and differences. Category counts include the structure attributed to each content item. Generated output absent from retained history is excluded from context and reported as `discardedTokens`. Cache includes read/write classified totals, differences and read categories. `attribution:estimated` uses same-model observations for identical tool definitions, concatenated-text BPE counts, Harmony framing and native reasoning usage. Sampling sequences bind responses to retained items. New threads enable `experimentalRawEvents`; the current resume API has no opt-in field. Attribution persists independently of rollout history. Threads awaiting native usage return `source:preview` with unknown totals. The response includes unused capacity and diagnostic ledgers.
  Context categories classify `generic.developer_instructions` as `custom` (custom developer instructions), separately from runtime developer instructions and mid-session injections. Input, output and cache ledgers use the same categories.
  Tool update notices add `toolUpdates:[{name,kind:added|updated|unchanged,changes:[{field,kind:added|updated|removed,diff}],definition}]`. Each notice retains its full text; changes compare against previously recorded definitions, and `definition` contains the complete new tool declaration.
- `PATCH /machines/{m}/threads/{t}/settings` accepts native fields `model,effort,serviceTier,collaborationMode,approvalPolicy,sandboxPolicy,cwd` and returns current state plus `appliesTo:activeTurn|nextTurn`. The `reasoningEffort` alias maps to `effort`. Standard speed uses `default`, Fast uses the model catalog tier ID (`priority`), and Ultrafast uses `ultrafast`.
  Creation and settings updates accept `saveDefaults` with explicitly selected fields from `model,effort,serviceTier`. Nexus saves the default model and remembers effort, including Ultra, and speed by model. A model switch with `saveDefaults` fills omitted effort and speed from that model's preferences or catalog presets. Permission selections apply to the conversation.
- `POST /machines/{m}/threads/{t}/messages` `{text,input?:native[],clientUserMessageId?,actor?:human|agent|tool,actorName?,model?,effort?,serviceTier?,collaborationMode?}` → `{turnId,mode:start|steer}`. The optional client ID passes through to native user-message `clientId`.
  Attachments upload original files to `{cwd}/.nexus/attachments/{uploadId}/` on the execution machine before sending. File uploads, including image files, use native text items containing `Attached file: /absolute/path`. Image uploads use native `{type:"localImage",path}`. Native inline `image` inputs remain accepted by the API.
- `POST /machines/{m}/threads/{t}/messages/{itemId}/edit` `{turnId,text,actor?,actorName?}` → `{turnId,mode:start}`. Stops any active turn, calls native `thread/revert` before the target turn, and starts its replacement in the same thread. Retains earlier user inputs in that turn and non-text inputs from the edited message. Later inputs and replies are removed; files retain their current state. Empty text requires retained non-text input. If starting the replacement fails after reversion, the error's `data` contains `{reverted:true,inputPrefix,attachments}` for resending via `/messages`.
- `POST /machines/{m}/threads/{t}/resume` `{turnId}` → `{turnId,mode:start}`. Requires the specified turn to be the latest and interrupted; otherwise returns HTTP 409. Starts a new native turn with `input:[]`, retaining saved context and adding no user message. Restores archived threads before starting. MCP exposes this as `resume_turn(machine_id,thread_id,turn_id)`.
- `POST /machines/{m}/threads/{t}/messages/{itemId}/regenerate` `{turnId}` → `{turnId,mode:start}`. Removes the selected assistant message and later history in the same thread, preserving earlier same-turn messages, attachments, reasoning and tool records. Interrupts an active turn, rebuilds the retained prefix, and continues with empty input. Supports archived threads and side conversations.
- `POST /machines/{m}/threads/{t}/turns/{turnId}/regenerate` `{actor?,actorName?}` → `{turnId,mode:start}`. Reverts before the selected turn and resubmits all its user inputs and attachments in order. Input-free turns restart with empty input. Earlier turns and current files are retained. Stops active work after validating the target and supports archived/side conversations. Replacement-start errors expose `{reverted:true,inputPrefix,attachments}` for resubmission through `/messages`.
- `POST /machines/{m}/threads/{t}/fork` `{turnId?,lastItemId?,lastTurnId?,beforeTurnId?,cwd?,model?}` → `{thread,machineId}`. `turnId` with `lastItemId` includes that completed assistant message, including within an active turn; turn boundaries retain their native behavior. Choose one boundary or omit boundaries for the latest history. Ordinary forks persist the source title with an incrementing `(2)`, `(3)` suffix; numbering includes archived siblings and continues across nested forks. A side-chat source creates a sibling side chat under the same main thread, retaining its side policy, shared context and inherited-history cutoff. Side forks use the next side-chat number, expose `thread.sideConversation`, remain hidden from main lists/search and emit `nexus/side/created`.
- `GET /machines/{m}/threads/{t}/sides` → `{data:string[],names:{threadId:name}}`. Saved side-thread IDs for this parent, in creation order; available while the machine is offline. Remaining side conversations retain their numbers after deletion.
- `POST /machines/{m}/threads/{t}/sides` → `{thread,machineId}` (201). Forks the latest recorded context without interrupting the parent, then injects the side policy and inherited-history boundary before accepting messages. Paginated parents use native `attachToSource`; legacy forks retain an inherited-turn cutoff. Side histories and snapshots expose new turns in `data`. Side metadata adds `sideConversation:{parentThreadId,createdAt,sharedContext:[{id,items}]}`. Shared context contains the latest inherited turn's messages, reasoning and tool records. Codex's persisted `history_base` byte boundary fixes the prefix; public history supplies normalized items, completed command output comes from that prefix, and pending model tool calls retain their arguments without later results. Associations and shared context persist in `search.sqlite`; side threads use `threadSource:nexus-side` and stay out of main lists and search. `nexus/side/created` carries `{threadId,parentThreadId}`. Sending, settings, attachments, requests and interruption use the ordinary thread endpoints.
- `DELETE /machines/{m}/threads/{t}/sides/{sideId}` → `{deleted:true}`. Deletes the associated Codex thread, including a running side chat, and its Nexus record. The parent ID must match the saved association. `nexus/side/deleted` carries `{threadId,parentThreadId}`.
- `POST /machines/{m}/threads/{t}/interrupt` `{turnId?}`.
- `POST /machines/{m}/threads/{t}/archive` `{discardEmpty?}`. When `discardEmpty` is true, deletes a new thread that has never started a turn and returns `{deleted:true}`. Otherwise archives the thread.
- `POST /machines/{m}/threads/{t}/unarchive`; `POST .../rename` `{name}`.
- `POST /machines/{m}/threads/{t}/compact`; `POST .../review` native `target` and optional `delivery`.
- `GET /machines/{m}/threads/{t}/skills|mcp` → native skill or MCP inventory scoped to the thread.
- `GET /machines/{m}/threads/{t}/diff` → `{diff,exitCode}` including tracked working-tree changes and untracked files.
- `GET /machines/{m}/threads/{t}/background-tasks` → `{data:Task[],nextCursor}`. Task uses native `processId,command,cwd,itemId`.
- `POST /machines/{m}/threads/{t}/background-tasks/{processId}/terminate` → `{terminated}`.
- `POST /machines/{m}/threads/{t}/background-tasks/clean`.
- `GET /requests?machineId=&threadId=` → `{data:Request[]}`. Request: `{id,machineId,threadId?,turnId?,method,params,createdAt}`; `id` is a platform request key.
- `POST /requests/{id}/respond` `{result:<native result>}`.
- `GET /machines/{m}/models` → native `{data,nextCursor?}`.
- `POST /machines/{m}/rpc` `{method,params}` → `{result:<native result>}`.
- `GET /machines/{m}/threads/{t}/snapshot?limit=30` → `{thread,settings,tokenUsage,compactionIds,data,nextCursor,eventCursor:{epoch,id}}`. Loads recent turns through native `thread/resume.initialTurnsPage` and establishes an ordered snapshot boundary. Archived threads use a read-only history page.
- `GET /machines/{m}/threads/{t}/wait?timeoutSeconds=60&turnId=` → `{reason,thread,turn?|history?|requests?}`. Checks initial state, then waits for events. Reasons: `turn_completed`, `idle`, `input_required`, `system_error`, `timeout`, `disconnected`.
- `GET /events?machineId=&threadId=&after=&epoch=` → SSE `event: nexus`, `id: epoch:sequence`, `data: Event`. Accepts `Last-Event-ID` and numeric `after` cursors.

Event: `{id,epoch,machineId,method,params,time}`. Native methods and fields are retained. Platform methods include `nexus/machine/updated`, `nexus/request/created`, `nexus/request/resolved`, `nexus/threads/changed`, `nexus/history/changed`, and `nexus/resync`. Each service start has a new epoch. Retention gaps and epoch changes trigger resync. Native errors map to non-2xx `{error:{message,code?,data?}}`.

`nexus/search/updated` refreshes active search results as synchronization advances. `nexus/threads/changed` carries `{updated:Thread[],removedThreadIds:string[]}` for list updates; `nexus/history/changed` invalidates a thread changed outside its observed runtime. `search.sqlite` stores metadata, user/assistant messages, per-turn revisions, and an FTS5 index. Native events and filesystem events coalesce affected sessions; reads fetch changed/new turns and remove reverted or deleted content. Native `fs/watch` covers the Codex data directory and history tree, installing watches on new directories. Files trigger official history reads; metadata changes trigger newest-first inventory reads. Every five minutes, full inventory reconciliation covers missed notifications and unavailable watchers. Reconnection rebuilds watches and reconciles the inventory. Cached history remains searchable offline.

Assistant `item/completed` events add `params.item.nexusTps:{tokens,durationMs}` when reasoning summaries are disabled (`settings.summary: "none"`) and native `contentTokenCount` and the item's native start/completion timestamps are available. Nexus saves these measurements and message attribution in the `message_records` table of `search.sqlite` and includes them in history. TPS is `tokens * 1000 / durationMs`.

## Agent messaging

Bot identity is the lowercase final six characters of the native thread ID. Thread creation, lists, search and details expose `botId`. MCP `resolve_thread(thread_id,machine_id?)` resolves a short or full ID to `{botId,machineId,threadId}` using indexed history and observed sessions, with loaded-session discovery on a miss. Indexed addresses remain available offline. Ambiguous IDs return HTTP 409 with candidate addresses; optional machine scoping or the full ID selects a target.

MCP `whoami()` and `send_message` read the caller from request `_meta.threadId` through the MCP context. The model supplies no sender argument. `send_message(text,thread_id?:string|string[],machine_id?,group_name?,cc=false,input?,actor_name?,model?,effort?,service_tier?)` calls `POST /api/messages`. Supply either `thread_id` or `group_name`. `input`, when supplied, replaces `text`; the message header prefixes its first text item. Image and skill items are retained. `actor_name` optionally sets the UI attribution label; prompts use the sender's botId.

Headers are `From [sender]: text` for single delivery and plain broadcast, `From [sender], CC [other], [other]: text` for CC, and `In group [name], From [sender]: text` for group delivery. Each CC list contains all other recipients. Group delivery excludes the sender. Generated prompt labels and instructions use English; user content, names and paths retain their original text.

Delivered items retain `origin.delivery:{senderBotId,groupName,cc:string[],promptPrefix}` in snapshots, history and item events. The UI uses this metadata for the sender avatar, name, group and CC labels, and removes `promptPrefix` from displayed and copied text. Native input retains the complete prompt.

All recipients resolve before delivery starts. Delivery reuses native start/steer behavior and preserves each target's context. Single delivery returns `{senderBotId,botId,machineId,threadId,turnId,mode}`. Lists and groups return `{senderBotId,data:[Address & {turnId,mode}],errors:[Address & {error}]}`; successful deliveries continue when another machine fails.

Groups are a `state.json` dictionary from exact names to lists of `{machineId,threadId}`. MCP exposes `set_group(name,thread_ids)`, `list_groups()`, and `delete_group(name)`. HTTP endpoints:

- `GET /api/threads/resolve?threadId=&machineId=` → Address `{botId,machineId,threadId}`.
- `POST /api/messages` `{senderThreadId,threadId?:string|string[],machineId?,groupName?,cc?:false,text?,input?,actorName?,model?,effort?,serviceTier?,clientUserMessageId?}` → single or batch delivery result. HTTP callers supply `senderThreadId`; MCP supplies it from request metadata.
- `GET /api/groups` → `{groups:{name:Address[]},creationOrder:string[]}`. `creationOrder` preserves persisted creation order, oldest first. Editing membership preserves this order; deleting and recreating a group appends it.
- `PUT /api/groups/{name}` `{threadIds:string[]}` → `{name,members:Address[]}`. Resolves and deduplicates members before saving; new members exclude subagents, side conversations and archived sessions; existing members can be retained or removed, and existing groups can be emptied.
- `DELETE /api/groups/{name}` → `{deleted:true}`.
- `PUT /api/machines/{m}/threads/{t}/groups` `{names:string[]}` → `{groups:{name:Address[]}}`. Updates this session’s memberships in one save, preserves other members and allows empty groups. Subagents, archived and side sessions cannot join new groups; existing memberships can be removed.

Group messages persist in the `group_messages` table of `search.sqlite`. A public message is recorded once before fan-out, with `{id,sequence,groupName,senderKind:human|agent,senderBotId?,senderThreadId?,text,createdAt,status:pending|sent|partial|failed,revision,delivery}`. Completion updates the same record and its revision. `nexus/group/message` publishes `{groupName,message}` on creation and delivery completion. `nexus/group/updated` publishes `{groupName,members}`; `nexus/group/deleted` publishes `{groupName}`. These events use the existing global SSE stream.

- `GET /api/groups` also returns `summaries:{name:{messageCount,lastMessage}}` for list previews and activity sorting.
- `GET /api/bots` → `{data:[Address & {name,machineName,cwd,status?,recencyAt?,updatedAt?,createdAt?}]}` from tracked indexed and observed conversations, including offline indexed sessions. Excludes archived, ephemeral and side conversations.
- `GET /api/groups/{name}/messages?before=&limit=50` → `{data:GroupMessage[],nextCursor}`. Data is chronological; `before` and `nextCursor` are sequence cursors for older messages. Maximum page size is 200.
- `POST /api/groups/{name}/messages` `{text,clientMessageId?}` sends as the user to all members with `In group [name], From user: text`. Returns the batch result plus `message`. A repeated client message ID returns its saved result without resending.

Agent group sends also return `message`. Deleting a group removes its public message records; pending delivery returns HTTP 409 until completion. Member conversations and their history remain available.

## Runtime service contract

`from nexus.core import SessionService, NexusError`

`SessionService(data_dir:Path,demo:bool=False,nexus_url:str="http://127.0.0.1:8765",demo_config:Path|None=None)` exposes async `start()`, `close()`, `machines()`, `add_machine(body)`, `update_machine(id,body)`, `add_project(machine_id,cwd,create_directory=False)`, `remove_project(machine_id,cwd)`, `remove_machine(id)`, `connect_machine(id)`, `reconnect_machine(id)`, `disconnect_machine(id)`, `rpc(machine_id,method,params)`, `list_threads(machine_id=None,params=None)`, `history(machine_id,thread_id,cursor=None,limit=30)`, `send_message(machine_id,thread_id,body)`, `interrupt(machine_id,thread_id,turn_id=None)`, `resume_turn(machine_id,thread_id,turn_id)`, `get_requests(machine_id=None,thread_id=None)`, `respond_request(key,result)`.

Web Push subscriptions live in `state.json`; the private VAPID key is `push-private.pem`. Completion delivery runs outside the event dispatcher, suppresses repeated completion events, and removes expired subscriptions on HTTP 404/410. Notifications cover successful top-level turns within tracked projects; subagent turns are omitted. Enabling notifications also observes loaded sessions on all connected machines and newly started sessions. The VAPID subject defaults to the subscribing request's origin; `NEXUS_PUSH_SUBJECT` can provide a contact URI.

`service.events.subscribe(after=None,machine_id=None,thread_id=None,epoch=None)` is an async iterator of Event dictionaries. `NexusError(message,code=None,data=None,status_code=400)` carries the HTTP error. Returned SDK models are serialized with aliases and omitted nulls. Notifications go to the event broker; server requests remain pending until explicitly answered, without blocking unrelated sessions. `rpc` requires a connected machine and returns HTTP 503 immediately otherwise. Native RPC replies have a 30-second deadline; timeout triggers reconnection. Aggregate lists surface individual host failures in `errors`.

Concurrent connection requests share one attempt. Connecting and restoring observations share a 30-second deadline, followed by transport cleanup with a five-second limit. Disconnect cancels an in-progress attempt and its retry. Each machine's session list query has a 15-second deadline.

`thread_state(machine_id,thread_id)` attaches the connection as an observer and returns resolved settings and native usage. Side conversations without native usage restore the latest saved token count along their fixed fork-history boundary, including nested forks; subsequent native usage updates replace it. `update_thread_settings(machine_id,thread_id,settings)` persists native settings and applies active-turn changes when supported by Codex. Each opened conversation explicitly subscribes to its turn/item stream; the SDK router delivers all observed turn events to the gateway. CLI and platform inputs share this stream. Initial context restoration uses one native resume; regular history stays paginated.

Session indexes include readable conversations and Nexus-created empty threads. Metadata-only runtime entries without readable turns are omitted, and history pagination continues to fill the requested page. Empty threads created through Nexus retain their original timestamps until the first turn and remain available for opening, archiving, restoring, and sending. Observer restoration checks empty entries before resuming them.

`fork_thread(machine_id,thread_id,params)` creates and names a fork using native RPCs, with serialized numbering per machine.

`regenerate_message(machine_id,thread_id,item_id,body)` serializes with message submission. MCP exposes `regenerate_message(machine_id,thread_id,turn_id,item_id)` and message boundaries on `fork_thread` as `turn_id,last_item_id`. `message_history.py` reads raw rollout prefixes, including compressed and inherited history. A native fork/revert retains earlier turns; Nexus drains the new recorder through archive, appends the retained partial turn with fresh ordinals, then unarchives and resumes it. Original rollout files remain intact. Nexus suppresses intermediate lifecycle notifications and releases waiting history reads with `thread/reverted` after rebuilding.

`regenerate_turn(machine_id,thread_id,turn_id,body)` restarts the whole native turn under the same submission lock. MCP exposes `regenerate_turn(machine_id,thread_id,turn_id)`.

`edit_message(machine_id,thread_id,item_id,body)` serializes with message submission on that thread. MCP exposes `edit_message(machine_id,thread_id,turn_id,item_id,text,actor_name="MCP")`.
